Method

Simulated traffic goes in, a neural network picks the green split, and a second-by-second junction model measures what happens to the queues.

The pipeline

  1. 1

    Simulate demand

    Hourly volumes for North, South, East and West follow a daily pattern: a morning peak that loads North, an evening peak that loads South, and a lunchtime surge on East and West. Vehicles arrive randomly (Poisson) at the rate set by the hour.

  2. 2

    Read the detectors

    Each cycle the controller counts arrivals on every approach, converts them to vehicles per hour and smooths them with an exponential average (weight 0.35 on the newest cycle). Counts over 90 seconds are noisy, so the model is trained on noisy readings.

  3. 3

    Predict the green split

    A neural network with two hidden layers of 16 units takes the four smoothed volumes and returns the North–South green time. East–West gets the remainder of the 80 seconds of green.

  4. 4

    Run the junction

    The simulator releases queued vehicles during green, adds the 5-second amber periods, and records every vehicle's waiting time through a full 24 hours.

Training data

The file data/traffic_training_data.csv has 15,000 rows. Seventy percent are drawn from the daily demand pattern with random scaling, and thirty percent are uniform random volumes so the network also sees unusual situations. Each row holds the four noisy sensor readings (about 18% error), the four true volumes and the ideal green time.

Where the labels come from

The ideal green time uses the equal degree-of-saturation rule from Webster's signal-timing method. Each phase is limited by its busiest approach, with flow ratio y = volume ÷ 1,800, and green time is shared in proportion to y:

green_NS = 80 × y_NS ÷ (y_NS + y_EW), limited to 10–70 s

So the network learns to imitate a sound engineering rule, but from noisy detector readings instead of exact volumes. Its value is that it handles noise and produces a single compact model that also runs in the browser demo.

Limitations

This is a prototype on simulated data. The junction is simplified: no turning movements, pedestrians, buses, multiple lanes or neighbouring junctions. The labels come from a formula rather than from real optimal timings, so the network can approximate that rule but cannot beat it. A real deployment would need measured traffic counts and testing against a calibrated simulator before any change to a live signal.
